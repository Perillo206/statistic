Homework 1: Private Key → Public Key (ECDLP)

Scalar multiplication over the toy elliptic curve y² ≡ x³ + 7 (mod 17), discrete lattice visualization, and a statistical look at the one-way behaviour of kG.

1. Mathematical Model & Ethereum Curves

In Ethereum, a public key is derived from a private key k by elliptic-curve scalar multiplication on the standard curve secp256k1:

Q = k·G = G + G + … + G (k times)

The forward map k → Q is fast thanks to the double-and-add algorithm (about log₂k doublings and additions). Recovering k from Q and G is the Elliptic Curve Discrete Logarithm Problem (ECDLP), infeasible for a 256-bit prime field.

For exploration we use a toy curve with the same Weierstrass coefficients as secp256k1 (a = 0, b = 7) over the small field F₁₇:

E(F₁₇): y² ≡ x³ + 7 (mod 17), assignment base point G = (1, 5)

#E(F₁₇) = 18 points (17 affine points plus the point at infinity O). The order of G depends on the chosen point (see section 2).

    5. Critical Discussion: Scalar Multiplication vs Cryptographic Hash Functions

    Both k ↦ kG and a hash such as SHA-256 or Keccak-256 are used as one-way functions, but they are built for different jobs. Scalar multiplication is a one-way structure-preserving map, which is what makes public-key cryptography possible. A hash is a one-way structure-destroying map, which is what makes it good for integrity and commitments.

    PropertyEC scalar multiplication (k ↦ kG)Cryptographic hash (Hash(m))
    Injectivity vs. CompressionInjective on the subgroup: distinct k mod n give distinct points, so no entropy is lost. Compression appears only if one keeps x alone (kG and −kG share x).Compressing by design: arbitrary-length input to a fixed digest, so collisions exist (pigeonhole) but are infeasible to find.
    Strict Avalanche CriterionNot satisfied. Coordinates jump non-linearly, yet Qk+1 = Qk + G, so successive outputs are algebraically linked.Satisfied in practice: flipping one input bit flips about 50% of the output bits, with no residual correlation.
    Algebraic HomomorphismPreserved: (k₁+k₂)G = k₁G + k₂G. Essential for Diffie–Hellman and ECDSA.Destroyed: Hash(m₁+m₂) is unrelated to Hash(m₁), Hash(m₂). Any linearity would be a security flaw.
    One-Wayness (preimage resistance)Rests on the hardness of the ECDLP. Generic attacks (baby-step giant-step, Pollard ρ) cost about √n, so a 256-bit curve gives roughly 128-bit security. Trivial for the toy field.No algebraic shortcut known; generic preimage search costs about 2m for an m-bit digest (256 bits for SHA-256).
    Uniform bitstring indistinguishabilityNot satisfied: encoded points are not uniform strings (only some x values occur, and (x, y) must satisfy the curve equation). Protocols hash or re-encode points before using them as random bits.Designed so that digests look uniformly random to any efficient observer (modelled as a random oracle).
    Core purposeAsymmetric key pairs, key exchange, digital signatures.Data integrity, commitments, proof of work, content addressing.

    Takeaway: the statistics in section 4 show a pseudo-random-looking walk, but it is generated by a simple group law; a hash deliberately hides any such structure.
